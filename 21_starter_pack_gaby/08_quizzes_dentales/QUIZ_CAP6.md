### Pregunta 1

¿Cuál de las siguientes es una herramienta de static analysis (análisis estático)?

A) JMeter
B) Selenium
C) SonarQube
D) Jira

<details>
<summary>Respuesta</summary>

**C) SonarQube.** Analiza código sin ejecutarlo. JMeter es performance, Selenium es test execution, Jira es bug tracking.
</details>

### Pregunta 2

Estás adoptando un nuevo software de historia clínica. ¿Cuál es el PRIMER paso?

A) Comprar el software
B) Assessment (evaluar qué necesitás)
C) Rollout a toda la clínica
D) Capacitar al equipo

<details>
<summary>Respuesta</summary>

**B) Assessment.** ISTQB dice que el primer paso es evaluar: ¿qué problemas resuelve? ¿realmente la necesitás? Antes de comprar.
</details>

### Pregunta 3

Una herramienta de testing puede dar "falsa sensación de cobertura". ¿Qué significa esto?

A) Que la herramienta detecta más defects de los que hay
B) Que pasar los tests automatizados no garantiza que el software sea bueno
C) Que la herramienta consume mucha memoria
D) Que la herramienta es lenta

<details>
<summary>Respuesta</summary>

**B) Que pasar los tests automatizados no garantiza que el software sea bueno.** Los tests automatizados solo verifican lo que está escrito. Si lo escrito está mal o falta, los tests pasan pero el software sigue roto. Mismo principio que confiar solo en el autoclave sin validar el instrumental.
</details>

### Pregunta 4

Selenium es una herramienta de:

A) Test management
B) Bug tracking
C) Test execution / automation
D) Static analysis

<details>
<summary>Respuesta</summary>

**C) Test execution / automation.** Ejecuta tests de aplicaciones web automáticamente.
</details>

### Pregunta 5

El proceso de adopción de herramientas según ISTQB es:

A) Comprar → usar
B) Assessment → PoC → selección → pilot → rollout → review
C) Pilot → rollout
D) Selección → compra → capacitación

<details>
<summary>Respuesta</summary>

**B) Assessment → PoC → selección → pilot → rollout → review.** Son los 6 pasos formales.
</details>

### Pregunta 6

Un beneficio de las herramientas de testing es:

A) Reemplazan al tester humano
B) Permiten escalar el testing (más tests en menos tiempo)
C) Eliminan la necesidad de un test plan
D) Garantizan que no hay defectos

<details>
<summary>Respuesta</summary>

**B) Permiten escalar el testing.** Las herramientas NO reemplazan al humano (A es falsa), no eliminan el test plan (C), ni garantizan nada (D).
</details>

<details>
<summary>Respuesta</summary>

</details>

### Pregunta 8

Una herramienta de performance testing (como JMeter) sirve para:

A) Detectar bugs en el código
B) Medir velocidad y carga del sistema
C) Hacer seguimiento de defectos
D) Gestionar el plan de testing

<details>
<summary>Respuesta</summary>

**B) Medir velocidad y carga.** Performance = cuánto tarda, cuántos usuarios aguanta.
</details>
