# Glosario Dental ↔ ISTQB

> **Mapeo bilingüe** de términos ISTQB a tu lenguaje profesional. Útil para el examen y para cuando tengas que hablar con desarrolladores.

| ISTQB (EN) | ISTQB (ES oficial) | En lenguaje dental |
|---|---|---|
| Acceptance testing | Pruebas de aceptación | Vos probás el software y decís "OK, lo adopto" |
| Acceptance criteria | Criterios de aceptación | Criterios de éxito del tratamiento (sellado, oclusión, estética) |
| Bug / Defect / Fault | Defecto | Caries, necrosis, fractura, lo no esperado |
| Bug report | Reporte de defecto | Epicrisis / nota de evolución de complicación |
| Boundary value analysis | Análisis de valores límite | Testear el paciente justo en el límite de edad/condición |
| Code coverage | Cobertura de código | Cuánto de la "pieza" se revisó |
| Component testing | Pruebas de componente | Probar un equipo por separado (autoclave solo) |
| Confirmation testing | Pruebas de confirmación | Re-test: "el arreglo anterior funcionó?" |
| Configuration management | Gestión de configuración | Control de versiones de protocolos, calibraciones, lotes |
| Decision table | Tabla de decisión | Combinaciones de condiciones (ej: dolor + infección) |
| Defect | Defecto | Imperfección en el producto |
| Dynamic testing | Pruebas dinámicas | Probar con el paciente presente, ejecutando |
| Error guessing | Adivinación de errores | Intuición clínica: "yo acá miraría bien" |
| Equivalence partitioning | Partición de equivalencia | Agrupar por comportamiento equivalente |
| Exploratory testing | Pruebas exploratorias | Sesión exploratoria con paciente complejo |
| Failure | Falla | Lo que el paciente reporta (dolor, fractura visible) |
| Functional testing | Pruebas funcionales | "¿El sistema hace lo que tiene que hacer?" |
| Incident | Incidencia | Evento que requiere investigación (complicación) |
| Integration testing | Pruebas de integración | Probar cómo se conectan los sistemas (RVG ↔ software) |
| Maintenance testing | Pruebas de mantenimiento | Probar después de cambios de entorno (Windows update) |
| Non-functional testing | Pruebas no funcionales | Velocidad, usabilidad, seguridad (atributos del "cómo") |
| Quality assurance (QA) | Aseguramiento de calidad | Proactividad: definir procesos y protocolos |
| Quality control (QC) | Control de calidad | Reactivo: verificar el producto terminado |
| Regression testing | Pruebas de regresión | "Lo que andaba, sigue andando?" |
| Requirement | Requisito | Lo que el paciente/paciente-sistema necesita |
| Risk | Riesgo | Probabilidad × impacto (complicación seria + probable) |
| Risk-based testing | Pruebas basadas en riesgo | Priorizar por urgencia clínica |
| Severity | Severidad | Impacto técnico (cuán grave) |
| Priority | Prioridad | Urgencia de resolución (cuándo arreglar) |
| Smoke testing | Pruebas de humo | "¿Arranca lo básico?" |
| State transition | Transición de estado | Cambios de estado del sistema (borrador → enviado → aprobado) |
| Static testing | Pruebas estáticas | Revisar documentos sin ejecutar (revisar historia clínica) |
| System testing | Pruebas de sistema | Probar todo el sistema completo |
| Test case | Caso de prueba | Protocolo paso a paso |
| Test condition | Condición de prueba | Lo que tiene que cumplirse |
| Test design | Diseño de pruebas | Diseñar cómo testear |
| Test execution | Ejecución de pruebas | Hacer el test |
| Test plan | Plan de pruebas | Plan de tratamiento escrito |
| Test procedure | Procedimiento de prueba | Pasos exactos a seguir |
| Test strategy | Estrategia de pruebas | Protocolo institucional |
| Testware | Producto de prueba | Lo que se usa para testear (datos, herramientas, docs) |
| User story | Historia de usuario | Motivo de consulta |
| Validation | Validación | "¿Funciona para el paciente/usuario?" |
| Verification | Verificación | "¿Hicimos lo que dijimos que íbamos a hacer?" |
| Walkthrough | Recorrido guiado | Ateneo clínico (presentación del residente) |
| Technical review | Revisión técnica | Reunión de expertos |
| Inspection | Inspección formal | Auditoría con roles y checklist |
| White-box testing | Pruebas de caja blanca | Testear mirando el código por dentro |
| Black-box testing | Pruebas de caja negra | Testear sin mirar el código |

## Términos adicionales útiles para el examen

| EN | ES | Explicación |
|---|---|---|
| Coverage | Cobertura | Cuánto del producto fue testeado |
| Cyclomatic complexity | Complejidad ciclomática | Qué tan complejo es el código (relacionado con bugs) |
| Defect density | Densidad de defectos | Cantidad de defectos por unidad (KLOC, por página, por función) |
| Entry criteria | Criterios de entrada | Condiciones para empezar a testear |
| Exit criteria | Criterios de salida | Condiciones para terminar el testing |
| Failure rate | Tasa de fallas | Cuántas fallas por unidad de tiempo |
| False positive | Falso positivo | El sistema dice "hay bug" pero no hay |
| False negative | Falso negativo | El sistema dice "no hay bug" pero sí hay |
| Peer review | Revisión de pares | Revisión por otro profesional del mismo nivel |
| Test coverage | Cobertura de pruebas | % de tests ejecutados / planificados |
| Test environment | Entorno de pruebas | Lugar donde se ejecutan los tests |
| Test estimate | Estimación de testing | Cuánto tiempo/dinero va a tomar |
| Test harness | Armazón de pruebas | Software de apoyo para ejecutar tests |
| Test log | Bitácora de pruebas | Registro de lo que se ejecutó |
| Test progress report | Reporte de progreso | Estado del testing al día |
