## 📋 El día del examen

### Mañana

- [ ] **Desayunar bien.** Proteínas + carbohidratos complejos (no solo café).
- [ ] **Hidratarte.** Llevar agua al examen (si te dejan).
- [ ] **Llegar 30 minutos antes.** Estacionamiento, baño, etc.

### Antes de entrar

- [ ] **NO repasar nada en los últimos 15 minutos.** Solo te vas a poner nerviosa con detalles.
- [ ] **5 minutos de respiración profunda.** 4-7-8: inhalar 4, sostener 7, exhalar 8. Repetir 3 veces.
- [ ] **Recordá: ya aprobaste al menos 1 sample exam.** Tenés el conocimiento.

### Durante el examen (60 minutos)

- [ ] **No te detengas en una pregunta mucho tiempo.** Si no sabés, marcá y seguí. Volvé al final.
- [ ] **Leé cada pregunta dos veces.** Las preguntas ISTQB a veces tienen "trampas" sutiles (palabras como "NOT", "EXCEPT").
- [ ] **Si dudás entre dos opciones:** buscá la que tiene el lenguaje más específico y concreto. Las respuestas vagas suelen ser incorrectas.
- [ ] **Cuidado con "todas las anteriores" y "ninguna de las anteriores".** ISTQB usa estas opciones — pensá bien.
- [ ] **Administración del tiempo:** ~1 minuto por pregunta. Si llevás 1.5 minutos en una pregunta, marcá y seguí.

### Después del examen

- [ ] **Salí tranquila.** No analices con otras personas que rindieron.
- [ ] **El resultado:** te lo dan al final del examen (en papel o pantalla) o por email en 1-2 semanas.
- [ ] **Si aprobás:** ¡FELICIDADES! Mirá [`../12_post_examen/QUE_HACE_DESPUES.md`](../12_post_examen/QUE_HACE_DESPUES.md).
- [ ] **Si no aprobás:** no es el fin del mundo. El 25-30% de la gente no aprueba al primer intento. Podés volver a rendir (pagando de nuevo, con cooldown de 1-2 semanas). Releé las secciones donde fallaste.

## 🎯 Lo mínimo que tenés que saber de memoria

### Los 7 principios

1. Testing shows the presence of defects, not their absence
2. Exhaustive testing is impossible
3. Early testing saves time and money
4. Defects cluster together
5. Beware the pesticide paradox
6. Testing is context-dependent
7. Absence-of-errors is a fallacy

### La cadena causal

Error → Defect → Failure

### Los 4 niveles

Component → Integration → System → Acceptance

### Las 8 categorías de herramientas

1. Test management
2. Bug tracking
3. Test data preparation
4. Test execution / automation
5. Static analysis
6. Performance testing
7. Test design
8. DevOps / CI/CD

### Los 6 pasos para adoptar herramienta

Assessment → PoC → Selection → Pilot → Rollout → Review

### Los 4 tipos de revisión

Informal → Walkthrough → Technical → Inspection

### Las 4 técnicas black-box principales

EP, BVA, Decision Table, State Transition

### Severidad vs Prioridad

- Severidad = impacto técnico
- Prioridad = urgencia

### Verification vs Validation

- Verification = ¿lo hicimos bien?
- Validation = ¿es lo correcto?

## ⚠️ Trampas comunes en el examen

| Trampa | Cómo evitarla |
|---|---|
| Confundir verification con validation | Memorizar las fórmulas |
| Confundir regression con confirmation | Regression = lo que andaba. Confirmation = el bug específico |
| Creer que "todas las anteriores" es la respuesta fácil | No siempre lo es. Pensá cada opción. |
| No leer las palabras "NOT", "EXCEPT", "ALL of the following" | Leer 2 veces |
| Asumir que testing = testing dinámico | Static testing también existe |
| Pensar que EP y BVA son sinónimos | EP = grupos. BVA = bordes |
| Decir que "ausencia de errores = éxito" | Es el fallacy (Principio 7) |
| Decir que el developer no debe testear | "Independencia" no significa prohibición total |

## 🛟 Si te ponés nerviosa durante el examen

1. **Respirá** — 4-7-8 (inhalar 4, sostener 7, exhalar 8)
2. **Pará 30 segundos** — cerrá los ojos
3. **Decíte a vos misma:** "ya estudié, ya sé esto"
4. **Mirar la pregunta como si fuera sobre odontología, no sobre software.** (Tu superpoder.)
5. **Si el pánico es mucho:** marcá todas las preguntas como "C" y seguí. Después volvé y revisá. Peor es dejar en blanco.
