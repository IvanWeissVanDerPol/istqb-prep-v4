## STATIC vs DYNAMIC (3.1.3)

| Static | Dynamic |
|---|---|
| NO ejecuta el código | SÍ ejecuta |
| Reviews + análisis estático | Test execution |
| Más temprano | Más tarde |

## WORK PRODUCTS (3.1.1) que se pueden testear

Requisitos, diseño, código, scripts, manuales, contratos, modelos.

## TIPOS DE REVIEW (3.2.4) ⭐

| Tipo | Líder | Formalidad |
|---|---|---|
| Informal | — | Baja |
| **Walkthrough** | Autor | Media-baja |
| Technical review | No autor | Media |
| **Inspection** | Moderator | Alta |

## PROCESO DE INSPECTION (3.2.2) ⭐

```
Planning
   ↓
Kick-off
   ↓
Individual preparation
   ↓
Inspection meeting (defects logged)
   ↓
Rework (author fixes)
   ↓
Follow-up (verificar fixes)
```

Mnemotécnico: "P-K-I-R-F"

## 5 ROLES (3.2.3) ⭐

- **Author** — crea el doc
- **Moderator** — facilita (no autor)
- **Reviewer** — busca defects
- **Scribe** — registra
- **Manager** — recursos, tiempo

Mnemotécnico: "MARS"

## FACTORES DE ÉXITO (3.2.5)

- Charter claro
- Reviewers competentes
- Tiempo de prep suficiente
- Material entregado a tiempo
- Checklist efectiva
- Cultura psicológica segura
