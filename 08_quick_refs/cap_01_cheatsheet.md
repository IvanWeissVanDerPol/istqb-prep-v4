## 7 PRINCIPIOS — memorizar al pie de la letra

1. **T**esting shows **P**resence, **N**ot absence of defects
2. **E**xhaustive testing is **I**mpossible
3. **E**arly testing saves time & money
4. **D**efects **C**luster together
5. **P**esticide **P**aradox (mismos tests no encuentran nuevos bugs)
6. **T**esting is **C**ontext-dependent
7. **A**bsence-of-errors is a **F**allacy

## CADENA CAUSAL

```
Error (humano) → Defect (código) → Failure (runtime)
```

## ACTIVIDADES

PLAN → MONITOR → ANALYSIS → DESIGN → IMPLEMENTATION → EXECUTION → COMPLETION

## TESTWARE (artefactos)

Plan · Cases · Procedures · Data · Scripts · Reports · Logs · Traceability matrix

## ROLES

- Test manager (gerente)
- Test lead (líder)
- Tester (ejecuta)
- Test designer (diseña)
- Test automation engineer (automatiza)

## INDEPENDENCE — 5 niveles

1. Mismo developer
2. Peer del mismo equipo
3. Test lead independiente
4. Equipo de testing interno
5. **Equipo externo** (máxima)

## QA vs Testing

- QA = proceso planificado (enfoque proactivo)
- Testing = actividad de QC (verificación)
- Testing forma parte de QC; QC forma parte de QA
