# Quiz Cap 3 (v4.0.1) — Static Testing

> **10 preguntas** — meta: **≥70% (7/10)**
> Tiempo: 12 min

---

**Q1. (LO 3.1.3) ¿Cuál describe mejor la diferencia entre static y dynamic testing?**

A) Static usa herramientas, dynamic no.
B) Static NO ejecuta el software; dynamic SÍ lo ejecuta.
C) Static es manual, dynamic automatizado.
D) Idénticos, solo nombre.

<details><summary>✅</summary>B. Static analiza work products SIN ejecutar. Dynamic los ejecuta.</details>

**Q2. (LO 3.1.1) ¿Cuál de los siguientes típicamente NO se evalúa con static testing?**

A) Requisitos.
B) Diseño.
C) Código fuente.
D) Reportes de uso en producción.

<details><summary>✅</summary>D. Static testing aplica pre-código o trabajo pre-producción. Datos post-producción no suelen pasar static review.</details>

**Q3. (LO 3.2.4) ¿Cuál es el tipo de review MÁS formal?**

A) Informal review.
B) Walkthrough.
C) Technical review.
D) Inspection.

<details><summary>✅</summary>D. Inspection es la más formal: tiene roles definidos, métricas, proceso estructurado.</details>

**Q4. (LO 3.2.4) En un walkthrough, ¿quién lidera?**

A) El moderator.
B) El AUTHOR del documento.
C) El scribe.
D) El manager.

<details><summary>✅</summary>B. Walkthrough es dirigido por el autor. Informal, sin roles formales.</details>

**Q5. (LO 3.2.3) ¿Cuál NO es un rol estándar en una review?**

A) Author.
B) Moderator.
C) Reviewer.
D) Procurador.

<details><summary>✅</summary>D. Los roles son Author, Moderator, Reviewer, Scribe, Manager. Procurador no existe.</details>

**Q6. (LO 3.2.2) ¿Cuál es la fase 3 del proceso de inspection?**

A) Planning.
B) Kick-off.
C) Individual preparation.
D) Rework.

<details><summary>✅</summary>C. "P-K-I-R-F" — Plan, Kick, **Individual prep**, Rework, Follow.</details>

**Q7. (LO 3.2.1) El feedback temprano y frecuente de stakeholders es valioso porque:**

A) Es un requisito formal ISTQB.
B) Detecta problemas cuando todavía son baratos de corregir.
C) Solo ahorra tiempo después.
D) Mismo beneficio que tardío.

<details><summary>✅</summary>B. Early detection = cheaper fixes = 1/10x del costo.</details>

**Q8. (LO 3.2.5) ¿Cuál NO es factor de éxito de una review?**

A) Charter definido.
B) Reviewers correctos.
C) Tiempo adecuado de prep.
D) Castigar al author por defects.

<details><summary>✅</summary>D. Cultura psicológica SEGURA, no blame.</details>

**Q9. (LO 3.1.2) ¿Cuál es un beneficio típico de static testing?**

A) Encuentra defects temprano.
B) Reemplaza 100% del dynamic testing.
C) Es más rápido que dynamic.
D) Solo aplica a software crítico.

<details><summary>✅</summary>A. Beneficio central: detección temprana. Reduce costo x10 vs dynamic.</details>

**Q10. (LO 3.2.4) ¿Una inspection tiene scribe formal?**

A) No, los defectos se reportan verbalmente.
B) Sí, scribe registra defectos y decisiones.
C) Solo en walkthroughs.
D) Solo en revisiones técnicas.

<details><summary>✅</summary>B. Inspection tiene scribe formal que registra defects. Informal reviews pueden no tenerlo.</details>
